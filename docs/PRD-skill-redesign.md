# PRD：Skill 系统重构 — 选品评估替换交易优化 + 快速查询模式

> 日期：2026-05-06
> 状态：待实施

## Problem Statement

当前 Agent 的 4 个 Skill 存在三个问题：

1. **交易优化 Skill 名不副实** — 实际内容是经济学理论框架（交易成本诊断、效用分析），缺少定价数据工具支撑。用户期望"怎么定价能多卖"，得到的却是"搜寻品/体验品/信任品"分类，承诺与能力不匹配。
2. **Skill 路由依赖 LLM 猜意图** — 市场调研、用户需求、选品评估三个 Skill 都接受关键词输入，SOUL 的路由表只看"输入类型"无法区分。MiniMax M2.7 指令遵从度低，路由准确性无法保证。
3. **缺少轻量级交互模式** — 用户只想查一个数据（如搜索量、价格带）时，也要触发完整 Skill 流程，等待 10+ 次工具调用。没有"问一句答一句"的快速通道。

## Solution

1. 将「交易模型」Skill 替换为「选品评估」— 聚焦"这个产品/品类能不能做"，组合使用市场调研和竞品分析的工具，输出综合判断而非理论框架。
2. 新增「快速查询」模式 — 用户直接输入具体问题或裸关键词时，最少工具调用直接回答，不触发完整 Skill 流程。
3. 交互层面区分两种入口 — 默认对话模式（快速查询），侧边栏 Skill 卡片触发完整分析。裸关键词给快速摘要 + 引导选方向。

## User Stories

1. 作为亚马逊卖家，我想输入 "bluetooth speaker" 直接看到这个品类的搜索量和价格带，这样我能快速判断值不值得深入了解
2. 作为亚马逊卖家，我想输入 "B0D1QFXM7K" 直接看到这个产品的评分、销量、价格，这样我能快速了解一个产品的基本情况
3. 作为亚马逊卖家，我想点击「市场调研」卡片后输入关键词，得到包含市场规模、趋势、竞争格局、机会点的完整报告
4. 作为亚马逊卖家，我想点击「竞品分析」卡片后输入 ASIN，得到包含产品对比、评论解读、痛点机会的完整报告
5. 作为亚马逊卖家，我想点击「用户需求」卡片后输入关键词，得到包含使用情境、效用层级、价值演算的完整报告
6. 作为亚马逊卖家，我想点击「选品评估」卡片后输入关键词，得到"能不能做"的综合判断（市场规模、竞争、利润空间、风险）
7. 作为亚马逊卖家，我想点击「选品评估」卡片后输入 ASIN，得到这个产品所在细分市场的机会评估
8. 作为亚马逊卖家，我想输入裸关键词后看到快速摘要，底部提示我可以选择方向做完整分析，这样我不用纠结选哪个
9. 作为亚马逊卖家，我想问 "foldable keyboard 的 CPC 多少" 直接得到数字和一句结论，不用等完整报告
10. 作为亚马逊卖家，我想在完整分析报告中先看到结论，再看详细数据，这样我能快速抓住重点
11. 作为亚马逊卖家，我想看到每个 Skill 方向的一句话解释（"市场有多大" "对手怎么样" "买家要什么" "能不能做"），这样我不用理解专业术语就能选对方向
12. 作为亚马逊卖家，我想在快速查询的回答末尾被引导到完整分析，这样我能自然深入
13. 作为首次使用的卖家，我想看到清晰的使用引导，知道可以问什么、怎么用，这样我能快速上手
14. 作为卖家，我想在选品评估报告中看到明确的结论（建议进入/不建议进入/待验证），而不是模糊的分析框架
15. 作为卖家，我想在选品评估报告中看到风险项和机会项的具体数据支撑，而不是纯定性判断

## Implementation Decisions

### 模块 1：Skill 知识源层

- 将「交易模型.md」替换为「选品评估.md」，重新定义执行步骤和报告模板
- 选品评估的执行步骤：解析输入（关键词或 ASIN）→ 核心市场数据 → 竞争格局 → 用户满意度（差评痛点）→ 综合判断与建议
- 选品评估的报告模板：市场概况 → 竞争壁垒 → 差异化机会 → 综合结论（进入建议/风险等级/关键指标）
- 选品评估组合使用关键词类 + 产品类 + 品类类工具，不引入新的数据工具
- 3 个保留 Skill 的内容暂不修改，待实测后调整

### 模块 2：SOUL 路由规则

- 新增「快速查询」路由规则：如果用户输入是具体问题（非完整分析请求），直接调用最少必要工具回答，不跑完整 Skill 流程
- 新增「裸关键词」路由规则：如果用户输入只有关键词/ASIN 无明确方向，调关键词详情 + 搜索结果给快速摘要
- 快速查询回答末尾统一加引导语："需要更深入的分析？选择左侧分析方向开始"
- 替换路由表中「定价/转化/成本 → 交易优化」为「能不能做/值不值得做 → 选品评估」
- Skill 触发方式从"LLM 判断意图"改为"prompt 中带 Skill 名"（由 UI 层组装）

### 模块 3：开场引导

- 更新开场示例，将 4 个方向的描述改为用户友好的表述：「市场调研」= 这个品类有多大，「竞品分析」= 对手怎么样，「用户需求」= 买家要什么，「选品评估」= 能不能做

### 模块 4：TOOLS.md 清理

- 移除 TOOLS.md 中的 PDF 生成规范（与 SOUL.md 的"操作边界"矛盾——SOUL 禁止文件操作，TOOLS 却写了 fpdf2 生成流程）
- 工具代号列表保持不变

### 模块 5：前端 QUICK_CARDS 修复

- 修复第 4 张卡片文案：当前示例文本是市场调研内容，不是交易优化
- 替换为选品评估相关文案

### 模块 6：前端 SKILL_PROMPTS 更新

- 替换第 4 项「交易优化」为「选品评估」
- 更新模板文本和 label

## Testing Decisions

- **验证方式**：用 "bluetooth speaker" 作为统一测试关键词，5 轮实测
  - 第 1 轮：快速查询（"bluetooth speaker 搜索量多少"）
  - 第 2 轮：市场调研完整报告
  - 第 3 轮：竞品分析完整报告（2-3 个 ASIN）
  - 第 4 轮：用户需求完整报告
  - 第 5 轮：选品评估完整报告
- **评估标准**：完整性（章节有无遗漏）、准确性（数据有无编造）、实用性（结论能否指导决策）
- **不写自动化测试**：Skill 内容是 LLM prompt，不是代码逻辑，无法用单元测试覆盖。验证靠人工实测。
- **brand-guard 测试**：已有覆盖，新增选品评估 Skill 不引入新的品牌名或工具真名，不需要新增规则或测试用例

## Out of Scope

- 前端两步式输入改造（输入框下方展开方向按钮）— P2 后续迭代
- 新增数据工具接入（潜力产品、竞品流量词、1688 货源）— 待实测后决定
- Skill 内容根据实测结果调整 — 实测后进行
- 侧边栏交互优化 — 后续迭代
- 快速查询的结构化输出模板统一 — 后续迭代
- 开场引导的 UI 改造（首次使用引导页）— 后续迭代

## Further Notes

- 选品评估本质是"组合使用市场调研 + 竞品分析工具，但换个视角输出结论"。不是新数据维度，是新分析视角。
- 当前 MiniMax M2.7 指令遵从度低，Skill 路由从"LLM 判断"改为"UI 层指定"是降低对 LLM 能力依赖的策略。
- 快速查询模式和完整分析模式可以后续进一步差异化：比如快速查询用更简单的 prompt 模板、限制工具调用次数上限等。
- 4 个 Skill 的报告模板后续可根据实测结果调整——当前模板偏重数据展示，结论不够突出，待验证后决定是否调整顺序（结论前置）。
