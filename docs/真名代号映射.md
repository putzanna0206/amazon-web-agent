## 已知泄漏风险与缓解

### ⚠️ MCP 工具真名仍会出现在 LLM 的 tool-use schema 里

即使 SKILL.md 全用代号，FastClaw 通过 MCP 协议把工具 schema 直接传给 LLM 时，工具名仍是真名（如 `mcp_sorftime_keyword_detail`）。

**缓解方案候选（待选定）**：
- (A) 在 FastClaw Fork 里加 MCP 工具 alias 映射层（首选，需查源码可行性）
- (B) 在 FastClaw 与 Sorftime 之间重起一个 MCP proxy，做工具改名（讽刺地，刚删了的 mcp-proxy/ 当时是补 header，可以参考代码骨架）
- (C) 验证 LLM 调工具时是否真的把 schema 名字暴露给用户——如果 schema 名字只在 LLM 思考内部使用，不在最终输出，则**当前 sanitize 兜底已经足够**

### ⚠️ Runtime 路径泄漏

`~/.fastclaw/agents/agt_641dd151f236281066ee/agent/skills/market-research/` 这种路径在 LLM 看到的工具结果或日志里可能出现。**部署到 FastClaw 时建议把目录名也改成代号**（如 `市场调研/SKILL.md`），保持源码与运行时一致。

## 维护规则

1. 修改 SKILL.md 加入新工具时，**先在此表加一行映射**，再用代号写进 SKILL
2. 修改 sanitize() 时，对照本表保证每个真名都有兜底正则
3. 这份文件应在 `.gitignore` 里？—— **不**，留在 git 里方便协作者维护，但**不部署**到 `~/.fastclaw/` 即可
